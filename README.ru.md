# SSD Guardian v0.1.2

[English guide](README.md)

Portable-утилита для Windows 11 x64. Показывает физическую запись по SSD, логические операции по процессам и файлам, предупреждает о длительной или интенсивной перезаписи.

## Запуск

1. Распакуйте `SSD-Guardian-v0.1.2-win-x64.zip` в новую папку и запустите `SSDGuardian.exe` из папки `SSD Guardian`. Среда .NET входит в архив.
2. Если мониторинг недоступен, нажмите кнопку запуска с правами администратора и подтвердите запрос UAC. Без повышения прав доступны интерфейс, настройки и демонстрация.
3. Закройте окно или нажмите «Свернуть в трей», чтобы наблюдение продолжалось. Для остановки выберите «Выход» в меню значка в трее.

По умолчанию интерфейс английский. Для переключения откройте **Settings → Language**, выберите **Русский** и сохраните настройки. Язык меняется сразу и сохраняется в профиле. Сохранённые записи прежних версий отображаются на языке, на котором были записаны.

Автозапуск включается в настройках по желанию. Он создаёт ярлык в папке автозагрузки текущего пользователя. При входе мониторинг с повышенными правами требует подтверждения UAC. Настройки, история аномалий и диагностический журнал хранятся в `%LOCALAPPDATA%\SSD Guardian`. История и журнал ограничены по размеру. Для отдельного профиля укажите `--data-dir "D:\путь"`.

Демонстрация доступна из окна или командой `SSDGuardian.exe --demo`. В деталях реального уведомления можно посмотреть файлы и причину, отложить уведомления по этому экземпляру процесса на час или явно подтвердить завершение одного процесса. Прогноз показывает объём *логических запросов записи* за сутки при сохранении наблюдаемой интенсивности.

## Как читать данные

- **Физическая запись** — объём передач, наблюдаемых Windows на уровне накопителя. Для каждого распознанного SSD доступны байты и операции за 10, 30 и 60 минут и за сеанс.
- **Логическая запись** — объём файловых запросов. Рейтинг использует экземпляры процессов с PID и временем создания. Для атрибуции нужны распознанный том и подтверждённый экземпляр процесса. Файловые запросы с неполными данными отмечаются отдельно.
- **Аномалия** — превышение порога вместе с признаками повторной записи и сопутствующим физическим I/O на том же SSD. Стартовые пороги на экземпляр процесса и SSD составляют 1 ГБ за 30 минут и 5 ГБ за 10 минут. По умолчанию обновление каждые 5 секунд. Для 30-минутной эвристики нужны пять активных пятиминутных интервалов из шести. Пороги и правила, включая сигнатуру NVIDIA, можно изменить в окне настроек и в `settings.json`.

В таблице процессов нажимайте на заголовок, чтобы переключать сортировку по убыванию, по возрастанию и по умолчанию. Стрелка показывает выбранный столбец и направление.

## Сборка и тесты

На Windows x64 используйте официальный SDK .NET 10.0.404 из [архива Microsoft](https://dotnet.microsoft.com/en-us/download/dotnet/10.0). Для сборки нужны пакеты NuGet, зафиксированные в `packages.lock.json`.

```powershell
.\build.ps1
# Для SDK, распакованного отдельно
.\build.ps1 -Dotnet 'C:\путь\к\dotnet.exe'
```

Скрипт запускает автоматические тесты, публикует автономную сборку, создаёт ZIP и файл SHA-256. Результаты в `artifacts`. Для проверки на конкретном ПК можно запустить `SSDGuardian.exe --tray --smoke-test --smoke-seconds 60 --smoke-output "C:\путь\smoke.json"`.

На тестовой машине с правами администратора выполните `dotnet run --project tests/SsdGuardian.Windows.Tests -c Release -- --live` для проверки восстановления ETW, контрольной записи и локального UDP-трафика. Команда `./tests/Measure-Guardian.ps1 -Executable 'C:\путь\SSDGuardian.exe' -Seconds 7200` проводит двухчасовой замер с отдельным профилем.
