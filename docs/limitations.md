# Известные ограничения MVP

- Байты `DiskIO` относятся к запросам хранилища, видимым Windows. Реальная запись во флеш-память зависит от кэша контроллера, сжатия и внутреннего усиления записи. Байты `FileIO` относятся к файловым запросам, которые Windows может буферизовать и объединять. Физическая запись по конкретному PID остаётся неопределённой.
- Часть ETW-событий лишена имени файла или пригодного PID. Файлы, записанные до начала наблюдения или закрытые до разрешения имени, могут попадать в неатрибутированную статистику. Из логической статистики исключаются операции paging I/O, чтобы сброс кэша не удваивал первоначальный запрос записи. Запись через отображённые в память файлы может быть видна только на уровне накопителя.
- Аномалия определяется эвристически. Физические записи другого процесса на том же SSD могут совпасть по времени с повторяющимися логическими запросами. Под подозрение могут попасть журналы баз данных, циклические логи программ, штатные локальные кэши и другие задачи с многократной записью в фиксированный диапазон. Признаки перезаписи могут складываться по нескольким достоверно известным файлам. Обычное копирование и последовательный рост файла сами по себе не проходят проверку повторной записи.
- Короткие всплески, нагрузка ниже порогов, недостаток сведений о пути, размере или диапазоне файла и физические сбросы за пределами окна могут скрыть аномалию. Диагностика NVIDIA проверяет совпадение имени процесса и файла, повторную запись и сопутствующую активность SSD. Её отдельный порог можно изменить в настройках.
- При потере событий или перерыве ETW итог сеанса неполный. Интерфейс показывает соответствующее предупреждение. Новые интенсивные писатели могут вытеснять менее активные записи из детальных окон и списков файлов. Итог сеанса по сохранённому экземпляру процесса ведётся отдельно. При заполнении ёмкости сеансового учёта сумма свёрнутых строк остаётся в категории «Прочие». Запись без подтверждённого процесса и запись без привязки к SSD показываются отдельно.
- Статус завершения экземпляра процесса требует надёжной привязки к PID и времени создания. Если событие завершения невозможно подтвердить, строка остаётся в категории без подтверждённого завершения. Сводка по EXE объединяет сохранённые экземпляры по достоверному полному пути. Вычисление аномалий по-прежнему использует скользящие окна отдельных экземпляров.
- RAID, Storage Spaces, виртуальные накопители, многодисковые тома и устройства с неясными характеристиками отображаются с неопределённым типом или привязкой, когда Windows не даёт надёжно определить физический SSD. Карта обновляется раз в минуту. Итог отключённого SSD сохраняется в памяти сеанса при наличии однозначного аппаратного идентификатора. Проверены локальные SATA SSD. Сценарий HDD проверен модельными событиями.
- Для приёма событий ядра нужны права администратора и свободная системная ETW-сессия. Штатный выход освобождает сессию. После перерыва приложение пытается переподключиться. При совпадении имени и собственного идентификатора приложение может освободить оставшийся от аварийного выхода сеанс. При несовпадении идентификатора, в том числе у сеанса старой версии, приложение ждёт его освобождения. Windows может временно буферизовать события на диск при отставании обработки. [Поведение ETW в реальном времени](https://learn.microsoft.com/windows/desktop/ETW/event-trace-properties)
- Завершение требует подтверждения и точного совпадения времени создания. Windows и утилита могут отказать из-за защиты процесса, общего системного хоста или недоступных сведений для проверки.
- Перенос распакованной папки меняет путь к EXE. Если включён автозапуск, после переноса выключите и включите его заново, чтобы пересоздать ярлык.
